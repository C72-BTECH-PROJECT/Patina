| `BASE_WEIGHTS` | `readBaseWeights()` **evaluated once at module load**. Defaults **PARSING 0.4 / GITHUB 0.35 / ASSESSMENT 0.25** (the comment's 0.3/0.4/0.3 example is stale — ignore). |

# 4. Supabase — schema, migrations, RLS, storage

Apply `supabase/migrations/*.sql` in filename order. All backend writes use the service-role client (**RLS bypassed**); RLS policies exist for a future direct-browser path and are almost all SELECT-only.

## 4.1 `20260823_create_profiles.sql`
- **Enum** `patina_user_role` = `('candidate','recruiter')` (extended with `admin` in migration 3).
- **Table `public.profiles`**: `id` uuid PK = FK→`auth.users(id)` CASCADE; `username` text NOT NULL (len 3–30, regex `^[A-Za-z0-9_]+$`); `first_name`, `last_name` NOT NULL; `role` enum NOT NULL; `phone` (null or E.164); `github_url` (null or `github.com/<user>` regex); `company_name`, `verification_info` nullable; `onboarding_completed` bool default false; `created_at`, `updated_at` timestamptz.
- **Index:** `profiles_username_lowercase_unique` UNIQUE on `lower(username)`.
- **Functions/triggers:** `handle_new_user()` (SECURITY DEFINER) inserts a profile row from `auth.users.raw_user_meta_data` — trigger `on_auth_user_created` AFTER INSERT ON `auth.users`. `set_updated_at()` — trigger `profiles_set_updated_at` BEFORE UPDATE.
- **RLS:** enabled. One policy: "Users can read their own profile" — SELECT, `auth.uid() = id`. **No INSERT/UPDATE/DELETE policy.**

**Asked about →** user roles / username rules / phone & github URL validation / auto-profile-on-signup / `updated_at` auto-touch.

## 4.2 `20260830_create_jobs_and_applications.sql`
- **Enums:** `job_status('draft','published','closed')`, `application_status('submitted','under_review','shortlisted','rejected','withdrawn')`.
- **Table `public.jobs`**: `id` uuid PK `gen_random_uuid()`; `recruiter_id`→`profiles(id)` CASCADE; `title` (2–160); `description` (≥20 chars); `required_skills` text[] NOT NULL **(cardinality > 0)**; `preferred_skills` text[] default `{}`; `experience_level`, `location` text NOT NULL; `status` job_status default `draft`; timestamps. Indexes on `recruiter_id` and `(created_at desc) where status='published'`. Trigger `jobs_set_updated_at`.
- **Table `public.applications`**: `id` PK; `candidate_id`→profiles CASCADE; `job_id`→jobs CASCADE; `status` default `submitted`; `submitted_at`, `updated_at`; **UNIQUE `(candidate_id, job_id)`**. Indexes on `job_id`, `candidate_id`, `status`. Trigger `applications_set_updated_at`.
- **RLS:** jobs — "Anyone can read published jobs" (SELECT `status='published'`, anon+auth), "Recruiters can manage their own jobs" (ALL, caller = `recruiter_id` AND profile role = recruiter). applications — candidate SELECT/INSERT own (INSERT also requires target job published), recruiter SELECT/UPDATE for their own jobs. **No DELETE policy; no candidate withdraw policy.**

**Note:** `applications` is **not referenced by `resumes`/`scores`** — analyses link directly to `candidate_id` + `job_id`, never to an application row.

**Asked about →** job postings schema / required-vs-preferred skill arrays / job status lifecycle / one-application-per-job / published-job visibility / recruiter job-ownership RLS.

## 4.5 `20260903_create_resumes_and_scores.sql`
- **Storage bucket** `resumes` — **private** (`public=false`), **no `allowed_mime_types` / `file_size_limit` in the migration**. (The live bucket was hand-created 2026-08-31 with a pdf+docx allow-list + 10 MB cap — see `ISSUES.md`; a fresh env won't have those.) Object path `<candidateId>/<uuid><ext>`, written by `analysis.controller.js`.
- **Table `public.resumes`**: `id` PK; `candidate_id`→profiles CASCADE; `job_id`→jobs SET NULL (nullable); `file_name`, `file_ref` (storage path), `raw_text_preview` text nullable; `contact` jsonb default `{}`; `skills` text[] default `{}`; `experience`/`education`/`projects` jsonb default `[]`; `project_links` text[]; `parser_version` text; `created_at`. - **Table `public.scores`**: `id` PK; `resume_id`→resumes CASCADE; `candidate_id`→profiles CASCADE; `job_id`→jobs SET NULL; `composite_score` numeric(5,2) NOT NULL; `subscores` jsonb; `weights` jsonb; `explanation` jsonb; `evidence_limited` bool default true; `created_at`. - No `updated_at` / triggers — both tables are insert-only/immutable.
- **RLS:** enabled. SELECT-only: candidates read own resumes/scores (`auth.uid() = candidate_id`); recruiters read resumes/scores whose `job_id` is one of their jobs. **No INSERT/UPDATE/DELETE policies — writes are service-role only.**
